# Making History 1 & Gold Editor 3.9

- Regions whose name has no spaces (WorldMoreRegions / MH2 names such as «BayOfBangkok») now show as «Bay of Bangkok» in the game when they are added to a scenario without their own text.
- New regionpack changelog entry «textos» (visible region names): renaming only the visible name of a region records it, and «Adapt» / «Apply changelog» write those names into the scenarios. WorldMoreRegions, WorldMoreRegionsRivers and WorldModern now record their region names with spaces («Bay of Bangkok»).
- «Redraw borders» has a border style selector: «MH1» (the original look, default) or «MH2», thin crisp lines measured on Making History II's map background (near-black land borders, teal sea borders). The chosen style is recorded in the regionpack changelog (`border_style`) and later saves, island outlines and background restores/imports use it; older changelogs keep the MH1 style.
- New «⇪ From MH2» button in the scenario editor: creates an MH1 scenario from a Making History II one (game or Workshop) on the WorldMoreRegions or WorldMoreRegionsRivers regionpack (made from MH2's map; it asks you to install one if neither is). It copies nations (colour, government, culture and MH2 flag), region owners, controllers, population, terrain and culture, historic nations, cities with their IPUs, ports and capitals, coal/metals/oil resources, units (armies, fleets and air forces, using the matching unit types of the scenario chosen as template, without its events) and the research those units need, plus wars and alliances when the MH2 scenario has them.
- «Adapt» (Compatibility with the map) between two regionpacks now follows the land: each region of the new map comes from the scenario region it overlaps most and keeps that region's owner, controller and historic countries, and each region that goes away ends in the new region overlapping it most, so cities, units and population are no longer lost (The Modern World Reloaded 1022 → WorldMoreRegions lost 571 cities before, none now) and regions no longer get the owner the regionpack had when it was made (India went to the United Kingdom, Indonesia to the Netherlands…). A region with the same name on both maps but in another place (WorldMoreRegions «Piedmont» is in North Carolina, the old one is Italy's; also Burgundy, Athabasca, Llanos) is treated as a different region: the old one's data goes to the region where it really is («Piemonte») and the new one comes from its own land.
- Saved game → scenario: «Create new scenario» no longer fails with «'charmap' codec can't encode character» in MHEditor.exe (log messages with symbols such as → broke the request on the Windows console).
- Saved game → scenario and «Save as new scenario»: the new scenario now shows up in the game menu under its own name (scenarioInfo.xml kept the base scenario's name, so the copy was hidden behind the original).
- Event templates (war effect, protection reaction, party events) now set strPlayer on the war action; without it the game could not create the treaty and the turn locked.
- **Validate** now checks scripted events and AI parameter blocks: variables that nothing fills, missing countries, regions and decisions, broken event chains, debug actions (ActDevMakePeace), one-shot effects on a trigger that repeats every turn (wars declared again after peace), regions transferred before the peace, peace without checking the war is still on, AI goals pointing to missing parameter blocks, undefined region lists, treaty proposals (declare war, peace) with no proposing player (strPlayer), which lock the turn, event wars against an alliance member (the whole alliance votes and humans must answer before ending the turn), random triggers at 0 % (they still fire 1 % of turns), AI default choices with a low nDefaultChoicePercent, and starting wars tied to a whole alliance (every member starts at war and the AI can escalate it into a world war). Each problem opens the event or object it is about. Also from the command line: `python tools/event_lint.py "<scenario>"`.
- «Adapt» / «Change regionpack» can move scenarios onto a regionpack drawn in other map coordinates when the regionpack has a `proyeccion.json`: positions of cities, resources and units are converted, a city the approximate projection drops into a neighbouring country goes back to its own country's nearest region, and same-named regions are compared allowing for that error.
- **Adapt to another regionpack**: fleets in a sea region the new map lacks move to the new sea overlapping it most (before they pointed to a missing region and the scenario had errors), ports facing a vanished sea move to the nearest sea, and an island whose source region is being replaced (Falklands → Falkland Islands) is now added before that source goes away.
- Starting wars against (or by) a member of an alliance now name that alliance on its side. Without it the game deleted the war when loading the scenario («had alliance facade … lone country»), so the scenario started at peace. «＋ New → War» and the MH2 import fill it in, skip two members of the same alliance and skip a war already covered by the alliance's war; **Validate** shows an error for wars that leave it out, and the «drags a whole alliance» warning no longer asks to empty an alliance the game requires.
