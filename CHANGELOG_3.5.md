# Making History 1 & Gold Editor 3.5

Version 3.5 fixes serious regressions in 3.4: saves that appeared to do nothing, GEOS errors while saving, one invalid region blocking all queued regions, rejected overlaps between new regions, and Install failing while the game was open.

- Scenario editor: «Tech from units» (in «⚔ Bulk units…» and as a Validate warning with a fix button) marks as researched, for the chosen countries, the research projects that unlock the units they already have, with their prerequisite chain, worked out from the scenario's own FactoryOutputUnit/ResearchProj data; preview first, undoable, written only on Save.
- Scenario editor: «Give forces to countries lacking them» (the new default in «⚔ Bulk units…»): per branch, only countries with no land units, no navy or no air force get one, reusing the base/random army sizing and the non-overlapping placement; landlocked countries get no navy, and units above a country's tech can be followed by «Tech from units».

## Fixes after tester feedback (FalloutNV / FalloutMojave)

- Save can no longer fail silently: any failure (server error, lost connection, unexpected editor error) shows a message, re-enables Save and keeps the pending edits. If the server did save but the page failed while showing the result, the edits are cleared and the regions reloaded instead of being saved twice.
- After **Install** as a new regionpack or **Save as…**, the window follows the regionpack the server now edits. Before, every later save was rejected with "the regionpack changed in another window" and reloading lost the pending work. That message now tells you to download the pending changes first.
- Fixed "internal error: AssertionFailedException: Unable to determine overlay result geometry dimension" when saving new regions that touch a neighbour's border. GEOS errors during a save are now retried with cleaned geometry and, if that fails, reported in plain words with the edits still pending.
- New regions that slightly overlap their neighbours save again. Several new regions drawn over each other before one save no longer end up with overlapping meshes (the first one drawn keeps the shared part), and a region drawn over land with a river or sea underneath no longer fails with "would have an invalid outline".
- The **Draft** button only appears after a failed save or while a downloaded draft has not been restored, and has a tooltip.
- The "Install now / Later" question is asked once per session and regionpack instead of on every save; the red banner with **Install** stays.
- Create region: the drawing closes only on a click within 8 px of the first point (the radius no longer grows with **Fit**), and **Fit** now follows existing borders from one region's outline to the next by the shortest border path, instead of cutting the corner with a straight line.
- Verified **All intersected regions** and chained pending cuts end to end on a copy of the tester's regionpack.
- Gaps between regions no longer slip through unnoticed: after a save, the editor looks for small gaps between the regions you just created or changed and their neighbours (in game: background specks, borders drawn only in part) and offers to close them at once.
- **Close gaps** (toolbar, region panel and the Validate button) now saves immediately when nothing else is pending. Before, it only queued the change «for the next Save», and the gaps stayed if Save was not pressed.
- Close gaps around one region no longer hands that region the slits that run between two other regions and only touch it at the tip; those go to the neighbour sharing the most border, so they actually close. A region completely surrounded by a thin gap is now detected.
- «Split among neighbours by proximity» no longer fails with an internal Voronoi error when two neighbours share border points.
- Fixed "internal error: not well-formed (invalid token): line N, column N" when saving or opening a regionpack or scenario whose XML was hand-edited (ANSI characters in a UTF-8 file, control characters, bare «&», «--» inside a comment). The editor now reads what the game reads; if a file really is broken, the message names the file and the line.
- A cut that covers a whole region now says so («the polygon covers the whole region») instead of "the mesh would be broken", and a save that refers to a region that no longer exists explains it instead of failing with an internal error.
- Close gaps and Validate no longer list gaps that exist only in the traced outline (the mesh already covers them) or crumbs under ~100 m²: they could never be closed and stayed in the list forever.
- Old borders in the background after updating a regionpack outside the editor: **Refresh → load the game's regionpack** now also discards the project's old background images (they hid the new ones, and a later Install would have copied them into the game). When the map already matches the game but the project still holds different background images, Refresh asks whether to discard them.
- Region panel: new **forced adjacency** controls that write map.xml for you. «Make neighbour of» adds a ConnectedRegions entry (regions become neighbours in game even if their polygons do not touch: lake shores, islands, straits); «Remove adjacency with» adds a DisconnectedRegions entry; existing links are listed with a remove button. They reach the game with Install.
- After a save, if a region you created or changed sits next to another land region without touching it and only a gap with no region (a lake, an erased river) lies between them, the editor offers to make them neighbours (ConnectedRegions).
- Drawing many new regions before one save works: when the new regions together cover an old region completely, that region is removed and what it had goes to the new region that took most of it (before: «the mesh of X would be broken», or «would come out with N degrees² instead of M», and nothing was saved). Two new regions drawn exactly on top of each other get a message that says so.
- Fixed a region's editable outline shrinking to a tiny crumb when its mesh held the same area twice (regression from 3.3).
- The check for gaps after a save runs once per group of nearby regions instead of once per region (20 new regions: from about 95 s to 10 s).
- «Back» now says what the last save contained (new regions, deleted regions, transfers) before undoing it.
- Added `python tools/check_save_robust.py <project folder>`: assert-based check (on a temporary copy) for the GEOS fallback, overlapping new regions and pending edits surviving a failed save.
- Fixed: «Close gaps» no longer fails with an internal error ("'NoneType' object has no attribute 'length'") when a repair would leave a region as a polygon plus a loose line; and in English, the save errors «World was not touched…» and «unexpected editor failure» are fully translated again.
